# 조사원별 기본 프로시저 + 폴백 검증 (2026-11-16, 배포된 서버)

## 변경
- 조사원에 `defaultProcedureId`(연결된 프로시저만 지정 가능, 아니면 400). 프로시저 라우팅이 0개를 고르면 활성 기본 프로시저를 붙이고 `procedureRouting=default`, 실행 로그 `routing.procedures[].fallback="default"`.
- 기본 프로시저는 라우팅 후보에서 제외한다(폴백 전용). `server/routing/index.ts`(selectProcedures)와 `augment`(후보 목록·기록) 모두.
- 조사원 58개 전부에 기본 프로시저 지정: 새 프로시저 17개 + 기존 6개는 `[기본] <이름>` 복사본으로 새로 만들어 지정(후보 제외 때문에 기존 구체 프로시저를 그대로 기본으로 쓰면 라우팅에서 사라진다). 코드 조사원 30개(코드: 29 + Flask)는 공용 `[기본] 소스 코드 구조·구현 설명` 하나를 쓴다. 데이터·적용: `default-procedures.json`, `default-procedures-apply.mjs`.

## 폴백 실제 확인
- 질의 `p4system에서 agent를 인스톨할 안내 웹페이지를 관리하는 곳은 어디인가?`
  - 적용 전(run 228): `코드: p4system / - : none` (프로시저 없는 쌍).
  - 적용 후(run 233): `코드: p4system / [기본] 소스 코드 구조·구현 설명 / default`, 라우팅 기록 `fallback: default`, 후보 0개. 웹 검색 쌍은 같은 구체 프로시저 2개 그대로.
- 관리자 조사원 폼에서 「기본 프로시저」 선택이 연결된 프로시저 + 「없음」만 보이고 저장된 값이 선택돼 있음을 확인(법률 용어 사전: `[기본] 용어 정의 정리`).
- 조사원 58개 모두 기본 지정, 기본이 연결 목록에 있음 58/58. 프로시저 총 92개(이전 75 + 17).

## 한계
- 기본 프로시저 내용은 모델이 쓴 범용 관점이며 답변 품질 개선은 측정하지 않았다.
- 도메인 조사원은 프로시저 라우터가 보통 최소 1개를 고르므로(topK 2, minScore 0) 폴백은 후보가 비는 조사원(코드, 크롤러 등)이나 LLM/오류 경로에서 주로 작동한다.
- 새 `[기본]` 복사본 6개는 원본과 내용이 같아 원본을 고치면 따로 맞춰야 한다.
