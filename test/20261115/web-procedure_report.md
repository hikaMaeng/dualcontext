# 웹 검색(덕덕고) 프로시저 확장 측정

- 변경: 웹 조사원에 연결된 프로시저를 일반 목적 3개(근거 신뢰도 점검, 수치·사실 추출, 비교 분석)에서 **질의 유형별 16개 추가 = 19개**로 늘렸다. `[웹] 최신 동향·뉴스 타임라인 · 사실 확인·교차 검증 · 시세·가격·환율 확인 · 일정·날짜·시간 확인 · 제품·서비스 비교 및 구매 가이드 · 후기·평판 요약 · 방법·절차 안내 · 장소·여행·이동 정보 정리 · 규정·정책·제도 변경 확인 · 개념·배경 설명 · 기술 문제 해결·사용법 · 조언·사례 정리 · 건강·의학 정보 정리 · 인물·기업·단체 정보 정리 · 쟁점·찬반 정리 · 실시간 현황·날씨 확인`.
- 측정: `web-procedure-eval.mjs` — 유형별 질의 34개(라벨은 작성자 판단, 질의마다 기대 프로시저 1~2개)를 `POST /router/preview` 로 보내 웹 조사원에서 고른 프로시저를 기대와 비교. 현재 서버의 프로시저 라우팅은 임베딩 상위 2개.
- 첫 측정(날씨 프로시저 추가 전, 32개): 웹 조사원 포함 31, 1위 적중 28, 상위 2개 적중 29. 빗나간 것 중 하나가 「날씨·미세먼지」 질의로, 해당 프로시저가 없어서 `[웹] 실시간 현황·날씨 확인` 을 추가했다.

## 프로시저 단계 margin 별 (날씨 추가 후, 34개, 상위 2개, 최소 유사도 0)
| margin | 선택 평균 | 기대 밖 선택 평균 | 1위 적중 | 상위 2개 적중 |
|---|---|---|---|---|
| 1 (현재 라이브: 항상 2개 채움) | 2.00 | 0.97 | 31 | 33 |
| 0.05 | 1.53 | 0.50 | 31 | 33 |
| 0.03 | 1.38 | 0.35 | 31 | 33 |
| 0.015 | 1.15 | 0.15 | 31 | 32 |

원본: `web-procedure-eval_m*.txt`. 모든 설정에서 웹 조사원이 포함된 질의는 34/34.

## 해석
- 프로시저를 늘려도 1위 적중은 31/34로 같고, 문제는 **둘째 자리**다. margin 1 이면 항상 2개를 채워 인물·개념·조언 질의에도 「제품·서비스 비교 및 구매 가이드」 같은 무관한 프로시저가 따라 붙는다(기대 밖 선택 0.97개/질의). margin 을 0.03 으로 좁히면 상위 2개 적중은 그대로(33)인데 기대 밖 선택이 0.35 로 준다. 0.015 는 한 건을 잃는다(32).
- 빗나간 질의: 「비타민D 먹으면 살 빠진다는 게 진짜야?」(기대: 사실 확인, 선택: 제품·후기). 임베딩이 「진짜」보다 「비타민D」(제품)에 끌린다.
- margin 은 **전역 프로시저 단계 설정**이라 모든 조사원에 적용된다. 다른 조사원의 프로시저 선택에 미치는 영향은 측정하지 않았다.

## 한계
- 라벨과 질의는 작성자가 만들었고 프로시저의 appliesWhen 과 질의 표현이 겹치게 썼을 수 있다(낙관적). 실제 사용자 질의로 확인하지 않았다.
- 선택된 프로시저가 최종 컨텍스트·답변 품질을 올리는지는 측정하지 않았다(올바른 프로시저를 고르는가만 측정).
