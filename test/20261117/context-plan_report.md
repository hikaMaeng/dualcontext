## 기각·미검증

- 반증된 가설: "사전 요구가 안 나오는 것은 질의가 단순해서"(run 234). 프롬프트 문구를 고친 뒤 같은 유형 질의에서 6건이 나왔다. 프롬프트 편향이 원인이었다.
- run 238(reevaluate)은 첫 답변 호출이 `chat produced no data for 180s` 로 실패해 `stop=answer-failed`. 두 시험을 동시에 돌려 공유 모델 서버가 바빴던 것으로 추정하나 서버 부하는 측정하지 않았다. 같은 컨텍스트의 증강 후 답변은 79,096ms 에 성공했다. 재시도 로직은 넣지 않았다.
- **보강 예산 분리의 실서버 검증 없음**: run 239 는 평가가 부족 0개를 내 `no-missing` 으로 끝났다. 이 경로는 단위 테스트(최초 계획이 maxItems 를 꽉 채운 뒤에도 보강이 새 아이템을 만든다)로만 확인했다.
- 프롬프트 주입 완화, 단일 실행 외의 반복 측정, 기존 `classic` 답변 품질 비교는 하지 않았다.
