# 증강 전 · 후 최종 답변과 로그 검증 기록

대상: 배포된 컨테이너(`127.0.0.1:18081`). 요구: 「컨텍스트를 증강시킨 뒤 최종 응답을 받아야 한다. 로그에는 최종응답이 나와야 한다」, 「컨텐츠 증강 전후로 바뀐 답변도 다 보여야 한다」.

## 수락 기준

| # | 기준 |
| --- | --- |
| 1 | 시험 실행이 증강된 컨텍스트로 최종 답변을 만든다. |
| 2 | 증강 전(질의만) 답변도 만들어 비교할 수 있다. |
| 3 | 두 답변이 시험 실행 화면과 실행 로그 상세에 보인다. |

## 실행 결과

질의: 「국내 대형 전력기업이 사우디 아라비아 풍력 프로젝트에 투자한 내용을 알려줘. 투자 규모와 회사 이름이 뭐야?」 (로그 `#6`, 라우팅 `embedding`, 선택된 쌍: 산업 뉴스(합성)/산업 이슈 영향 분석 ; 금융 시황 리포트(합성)/수치·사실 추출)

| 답변 | 소요 | 내용(요지) |
| --- | --- | --- |
| 증강 전(질의만) | 202.4초 | 「한국전력공사(KEPCO)」, 「약 1조 2,000억 원(약 10억 달러)」 |
| 증강 후(질의 + 컨텍스트) | 45.0초 | 「한화전기(가칭)」, 「20억 달러」, 「10GW 규모 풍력 발전소 건설 계약」, 출처 인용, 합성 데이터라 확인 필요, 컨텍스트에 한국전력 등은 명시되지 않았음을 밝힘 |

* 적재된 기사(`ds_industry_news`)의 제목은 「국내 대형 전력기업, 사우디 아라비아 풍력 프로젝트에 20억 달러 투자」, 본문은 「한화전기(가칭)」 가 10GW 계약을 체결했다는 내용이다. **증강 후 답변은 이 자료와 일치하고, 증강 전 답변은 일치하지 않는다.**
* 이 자료는 합성 데이터라 실제 사실이 아니다. 증강 전 답변이 「틀렸다」기보다 「자료와 다르다」가 정확한 표현이다. 증강 전 답변이 실제 사실과 맞는지는 판정하지 않았다.

## 화면 확인

| 확인 | 관측 |
| --- | --- |
| 실행 로그 목록 | `#6` 이 맨 위, 성공 표시 |
| 상세 `#6` | 두 답변 영역의 제목 「증강 전 답변(질의만) · 202.4초」, 「증강 후 답변(질의 + 증강된 컨텍스트) · 45.0초」, `answer-before`/`answer-after` 가 각각 위 내용으로 표시됨 |
| 설정 스냅샷 | 텍스트에 `"answer"`(답변 프롬프트) 포함 |
| 전체 소요 | 상세의 소요 시간 203.3초(두 답변이 병렬이라 긴 쪽에 가깝다) |

## 검증하지 못한 것

* 시험 실행 화면(`#try`)에서 답변 비교 표시와 「실행 중」 안내는 브라우저로 직접 누르지 않았다. 같은 컴포넌트(`AnswerCompare`)를 쓰는 로그 상세만 확인했다.
* 한 질의 한 번의 결과다. 증강 후 답변이 항상 더 낫다는 근거가 아니다(이 확장 정의의 이득은 아직 측정되지 않았다).
* 답변 생성 실패 경로(LLM 서버 중단)는 시험하지 않았다. 코드상 답변별 `error` 를 기록한다.
* 증강 전 답변 202초는 추론 모델의 긴 사고 출력 때문으로 보이나 원인은 확인하지 못했다. 두 호출을 병렬로 보냈으므로 서버 큐잉이 영향을 줬을 수 있다.
