# 사전 정의 조사원 · 프로시저와 질의 응답 점검

대상: `npm run deploy dualcontext` 로 배포된 컨테이너(`127.0.0.1:18081`). 원자료: `eval-queries_result.json`(`eval-queries.mjs` 의 출력).
설정: 라우터 임베딩(1단계 상위 2, 2단계 상위 1), 활성 라이터 「기본 조립」, 임베딩 `embeddinggemma2:mp`, LLM `qwen36-35b`.

* 인덱스: `ds_legal_terms` 에서 `pg_indexes` 로 확인한 결과 기본키와 `embedding_mrl` 의 HNSW(`vector_cosine_ops`)뿐이다. 전체 차원 컬럼에는 인덱스가 없다(요구대로).
* 제외한 데이터셋: `KFTC-MLP/finance_korean_QA_w_rp_text`(접근 제한 gated).

기준: 해당 분야 질의에서 **1순위 쌍의 조사원이 기대한 조사원인가**, 그리고 **상위 근거에 질의에 직접 답하는 항목이 있는가**.

| 시험 | 관측 |
| --- | --- |
| MRL 2단계 벡터 검색 | 「산지관리법 시행령에서 축산시설은 무슨 뜻인가?」 → 「「산지관리법 시행령」에서 “축산시설”의 의미」 항목이 근거에 포함(16초, 첫 호출은 조사원 임베딩 캐시 계산 포함) |

| 라이터 LLM 일괄 | `qwen36-35b` 로 3분 28초. 프로시저 기준으로 재분류하고 출처를 붙였으며, 판례 조사원 자료 3건이 질의와 무관함을 「적용 한계」에 스스로 적었다 |
| 라이터 쌍별 | 쌍 2개에 라이터 호출 2회(`writer: {mode: per_pair, calls: 2}`), 결과 사이에 구분선 1개로 이어 붙임(모델 없는 조립 라이터로 확인) |

## 발견한 한계(반증된 가정 포함)

* **항상 상위 N 개를 고른다.** 임베딩 라우터에는 최소 유사도 기준이 없어, 2번째 조사원이 질의와 명백히 무관한 경우가 9개 중 5개였다(법률 용어 질의에 의학, 의학 질의 2개에 판례, 날씨에 산업 뉴스, 김치찌개에 판례). 나머지 4개는 인접 분야(산업 뉴스 ↔ 금융 시황, 판례 질의에 웹 검색)였다. 라이터가 이를 무관 자료로 걸러 내기는 했지만(LLM 라이터 시험) 노이즈다. 해결책 후보: 라우터에 최소 유사도 또는 상위 N 이하 선택 허용.
* **프로시저도 항상 1개를 고른다.** 2단계 상위 1개가 약한 일치여도 채워진다(예: 판례 쌍에 「근거 신뢰도 점검」, 웹 쌍에 「수치·사실 추출」). 「근거 신뢰도 점검」 이 항상 적용 프로시저라 후보에 늘 남는 영향도 있다.
* **합성 데이터**(산업 뉴스, 금융 시황)는 사실이 아니다. 프로시저가 합성임을 표시하라고 요구하지만 기본 조립 라이터는 표시하지 않는다(LLM 라이터가 해야 한다).
* LLM 라이터 3분 28초는 느리다(추론 모델). 기본 라이터를 LLM 으로 바꾸면 MCP 호출이 그만큼 걸린다.

## 이 리포트가 검증하지 못한 것

* 정답의 사실 정확성(특히 의학 질의의 정답)은 판정하지 않았다. 근거가 질의에 직접 관련 있는지만 봤다.
* 쌍별 LLM 라이터, 라우터 임베딩 vs LLM 의 품질 비교는 하지 않았다(각각 한 질의로 동작만 확인).
* 질의 9개는 적재된 표본 안의 내용으로 만들었다. 데이터셋 전체에 대한 검색 재현율은 측정하지 않았다.
* 브라우저에서는 조사원 폼 로드, 라우터 · AI 서버 화면 표시만 확인했다. 저장 · 삭제 버튼 조작과 시험 실행 화면은 이번에 누르지 않았다.
* ko 외 언어 화면 렌더링은 확인하지 않았다(키 집합 일치만 `check-i18n` 으로 확인).
