# 실행 로그 건별 분석과 보완 기록

요구: 「기존의 실행 로그를 개별 건수로 분석해서 시스템을 보완할 부분을 찾아서 조치하라」, 「개별 건수마다 서브에이전트를 활용하고 각 건수에서 얻은 교훈과 수정 내용을 취합하는 구조로」.
출발점은 실행 로그 #36(사춘기 질의)에 대한 사용자의 두 가설이다.

* H1. 라우터가 무관한 조사원(소프트웨어 개발)을 배제하지 못한다.
* H2. 라이터가 만든 컨텍스트가 모델에게 강압적이라 컨텍스트 없이도 좋았을 답변이 컨텍스트에 종속돼 억제된다.

## 1. 방법과 한계

* 실행 로그 #6~#31, #34~#36 중 증강 답변이 있는 **29건**마다 서브에이전트 하나(sonnet)를 붙였다. 각자 로그 JSON 한 건과 관련 코드만 읽고(읽기 전용) 같은 기준표로 낸 보고(라우팅 · 컨텍스트 · 증강 전후 답변 비교 · H1 · H2 · 제안)를 내가 취합했다. 제외: #1~#5(초기 시험), #32 · #33(재시작 · 삭제 시험).
* **한계**
  * 서브에이전트의 「관련 / 무관」 판정은 사람이 검증한 정답이 아니다. 에이전트당 도구 호출 2~5회로 수집 자료를 읽은 판정이다.
  * 가설 두 개를 브리프에 넣었다(확증 편향 위험). 반증도 찾으라고 지시했고 실제로 반증이 나왔다(아래 H2).
  * #6~#35 로그에는 라우터 점수표가 없었다(점수 기록은 `ee58f56` 에서 추가). 28건에서 「배제된 조사원 중 필요했던 것」은 판정하지 못했다.
  * 합성(한국어 가상) 데이터가 섞여 있어 「정답」은 자료와의 일치이지 현실 사실이 아니다.
  * 11건은 증강 전 또는 후 답변이 300초에 끊겨(#9 · #11 · #13 · #15 · #17 · #18 · #20 · #25 · #28 · #29 · #30) 비교하지 못했다(원인은 이미 고친 undici 헤더 시간 제한).

## 2. 가설 판정(29건 집계)

| | 지지 | 부분 · 약한 지지 | 판단불가 | 반증 |
| --- | --- | --- | --- | --- |
| H1 무관한 조사원 · 자료가 컨텍스트에 실림 | 20 | 6(#6 · #10 · #14 · #15 · #19 · #28) | 2(#12 · #17) | 1(#35, 최소 유사도로 모두 정상 배제) |

| | 지지 | 부분 지지 | 판단불가 | 반증 |
| --- | --- | --- | --- | --- |
| H2 컨텍스트 · 프롬프트가 모델을 억제 | 2(#16 · #27) | 7(#8 · #20 · #25 · #26 · #29 · #31 · #36) | 9(#9 · #11 · #13 · #15 · #17 · #18 · #28 · #30 · #35) | 11(#6 · #7 · #10 · #12 · #14 · #19 · #21 · #22 · #23 · #24 · #34) |

**결론은 H1 · H2 모두 맞지만 H2 는 조건부다.**

* 컨텍스트가 **질의와 관련 있으면** 증강 후 답변이 증강 전의 환각을 바로잡았다(#6 한국전력 환각 → 자료의 기업, #19 · #22 · #23 의 GPU 사양 오류, #24 CVE 영향 버전 등). 이때는 같은 프롬프트 문구가 해롭지 않았다.
* 컨텍스트가 **무관하면** 같은 문구가 재앙이었다. #27(빵 반죽)은 증강 전 467자로 정확히 답했는데 증강 후는 「컨텍스트에 정보가 전혀 없어 추측해 설명할 수 없다」며 거절했고, #16(이미지 합치기)은 GIMP 절차를 아는 모델이 「절차가 명시되어 있지 않다」며 답하지 못했다.
* 두 가설은 연결돼 있다: **H1(무관 자료 유입)이 H2(위축)의 방아쇠**이고, 프롬프트의 「컨텍스트에 없으면 추측하지 말라」가 그 방아쇠를 거절로 바꾼다. #36 은 위축이 없었고(증강 후가 자료 5건 요약이 돼 일반 지식 체크리스트 · 상담 연락처를 잃음) 원인은 강압 문구보다 무관 자료 노이즈로 보인다는 것이 에이전트의 판단이었다.

## 4. 조치하지 않은 것(남은 과제)

* **식별자 검색 약함**: #25 는 CVE 세 건 모두 미적중(CVE ID 를 임베딩이 못 찾음), #29 는 Q-Sparse · FUNGI 중 하나도 수집 못함. 키워드/전문 검색과 섞는 하이브리드, 질의 속 식별자 존재 검증이 필요하다.
* **복합 질의 분해**: #8 은 휴업수당(법령)이 필요한데 판례 · 법령 조사원이 배제됐다. 질의를 하위 질문으로 나눠 라우팅하는 단계가 없다.
* **절차형(how-to) 질의용 프로시저 부재**: #16 은 6쌍의 프로시저 중 단계별 방법을 설명하는 절차에 맞는 것이 없었다.
* **웹 검색 자료는 유사도가 없어 자료 단위로 거르지 못한다**(#11 · #28).
* **프로시저 단계 최소 유사도 미보정**, **라우터 임베딩 단독의 한계**(#36 소프트웨어 개발 0.6856은 라우터가 못 거름: 자료 단위 기준이 막은 것이다).
* 같은 조사원 안의 근접 도메인(금융 vs 산업 뉴스)은 행 유사도 0.72 를 넘을 수 있다.

기계적으로 센 것(재실행 8건 중 증강 후 답변이 있는 4건 #20 · #8 · #31 · #29): 인용 번호가 컨텍스트에 없는 경우 0건, 컨텍스트에 없는 URL 0건, 「컨텍스트에 정보가 없다」류 거절 표현 0건(정규식으로 센 값이며 의미 판정은 아니다).

**확인된 것**
* 무관한 자료가 붙던 #36 · #27 · #16 은 이제 증강하지 않는다. 사용자가 지적한 「컨텍스트에 종속된 위축 · 거절」이 이 건들에서 사라졌다(이전: #27 증강 후 266자 거절 · #16 거절).
* 컨텍스트는 2~4배 짧아졌다(자료 중복 제거 · 무관 행 제거).
* 출처 번호가 컨텍스트와 일치한다(날조 URL 인용 없음).

**해결되지 않은 것(정직한 기록)**
* #25: 질의한 CVE 세 건(CVE-2010-3763 · CVE-2022-46505 · CVE-2024-21709)은 **여전히 자료에 없다**(자료 본문에 나온 CVE 는 CVE-2021-4246 · CVE-2022-43456 · CVE-2021-22396 뿐). 다른 CVE 행도 같은 도메인이라 0.72 를 넘어 들어온다. 식별자 검색은 이번 수정으로 풀리지 않았다.
* #36 처럼 라우터가 무관한 조사원을 고르는 것(0.6856)은 라우터에서 고쳐지지 않았다. 자료 단위 기준이 뒤에서 막는 것이다. 이 경우 웹 검색이 쓸 만했던 질의가 증강 없이 지나가는 부작용이 있다(웹 검색 설명을 시점 민감 정보 전용으로 좁힌 결과).
* #8: 휴업수당 항목은 법령 조사원이 선택되지 않아 증강 후 답변이 일반 지식으로 답했는데 조문 번호를 **제29조** 라고 썼다(이전 증강 전 분석은 제46조). 일반 지식은 출처 없이 틀릴 수 있다. 「자료가 없어도 일반 지식으로 답하라」는 프롬프트의 대가이며 이번에 처음 확인됐다. 조문 번호가 맞는지는 이 기록에서 법령 원문으로 확인하지 않았다.
* 900초 타임아웃 2건(#25 증강 후, #29 증강 전)은 서버 부하로 보이나 원인을 분리하지 않았다.
* 8건은 한 번씩만 돌렸다. 답변 품질의 우열은 판정하지 않았고, 위에 적은 기계적 지표와 구조 변화만 근거로 한다.
