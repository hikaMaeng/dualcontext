## Failures
* `sse-live-check` 의 첫 두 실행은 실패로 판정됐다: ① 대기 한도(120초)가 시험 실행(답변 2개 생성, 127초)보다 짧았다(검증 스크립트 문제, 실행은 `ok`). ② 기준이 「콘솔 오류 없음」이었는데 만들어지기 전 노드 문서의 404 가 콘솔에 찍혔다. 기준을 「404 외 콘솔 오류 없음 + 404 횟수 기록」으로 바로잡았다(이 404 는 이번 변경 이전부터 있던 API 계약이며, 이번 변경으로 줄지 않았다: 백오프를 넣었지만 노드가 생성되기 전 구간에서 요청이 계속 나간다).
* **실서버에서 확인하지 못한 것**: (a) `middle` · `high` · `xhigh` 실호출의 새 구조 하 응답 머리(`reflections` · `next`) — 이번 실행에서 하지 않았다(AI 서버가 느려 한 호출이 수십 분~시간). (b) 선택 시한 예산(`DUALCONTEXT_BUDGET_*`)을 걸고 돌린 부분 결과 — 단위 시험(`planContext` · `startRun` · envelope)으로만 확인했다. (c) 옛 방식 대비 **실제 AI 서버** 처리량 — 대조는 가짜 서버로만 했고, 옛 구조를 배포해 같은 질의를 돌려 비교하지 않았다. (d) 코드베이스 외 스레드(`cpu.regex`) 실서버 호출 — 크롤러 조사원은 만들지 않았다(단위 · `dist` 시험으로만).
* 대조 측정의 한계: 옛 방식은 HTTP 서버 1 + stdio 1 프로세스(합산 최대 6)로 가정했다. stdio 세션이 둘이면 옛 합산은 9 로 새 기본과 같고, 셋 이상이면 옛 구조가 새 기본(9)을 넘을 수 있다(새 구조는 소비자 수를 환경 변수로 올려 맞춘다).
